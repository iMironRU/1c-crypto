# Конституция книги

> Контракт с читателем и ограничитель для автора.
> Claude Code читает этот файл перед каждым действием.

---

## Что эта книга ЕСТЬ

- **Мини-курс прикладной криптографии для 1С-разработчика.** Восемь уроков по
  45 минут: от «зачем это вообще нужно» до диагностики отказов.
- **Рабочий код, а не описание.** Каждый пример запускается в демонстрационной
  конфигурации (`configuration/`), исходники лежат в `code/`.
- **Мост от бытовой аналогии к платформенному API.** Новая концепция всегда
  входит через образ из жизни и только потом получает имя и код.
- **Курс о том, где криптография встречается в реальных задачах 1С:** обмен по
  API, JWT, HTTPS, электронная подпись, хранение паролей.

## Что эта книга НЕ ЕСТЬ

- **Не курс математики.** Ни теории чисел, ни доказательств стойкости.
  Читателю нужно понимать, что делает алгоритм и когда его применять.
- **Не справочник по КриптоПро и не инструкция по установке провайдеров.**
  Установка описывается ровно в той мере, в какой нужна для запуска примера.
- Не разбор нормативных требований к электронной подписи.
- Не курс по информационной безопасности вообще: доступ, аудит, сеть — соседние
  темы.

## Фундаментальный принцип: всё — двоичные данные

Самое важное, что читатель должен понять до первого примера.

> Криптография работает только с байтами. Не со строками, не с числами, не с
> датами — только с последовательностями байт (`ДвоичныеДанные`).

```
Строка → ДвоичныеДанные → [крипто-операция] → ДвоичныеДанные → Base64 / HEX / хранилище
```

Из этого следуют два обязательных шага в **каждом** примере:

1. Где на вход идёт текст — явно показано преобразование строки в
   `ДвоичныеДанные` перед операцией.
2. Где результат двоичный — явно показано, как его представить (Base64, HEX)
   и как сохранить в базе.

**Прятать это внутри функции без объяснения нельзя.** Читатель должен видеть
каждый шаг. Подробно — `docs/binary-data.md`.

## Принципы изложения

1. **Аналогия — точка входа, а не украшение.** Каждая новая концепция вводится
   через бытовой образ *до* технического объяснения.
2. **Каждый пример воспроизводим.** Нужны подготовительные шаги (установить
   сертификат, создать файл) — они описаны явно и пошагово прямо перед кодом.
3. **Смысловой блок — 300–500 слов.** Больше — делится на подразделы.
4. **Урок — 45 минут.** Это единица планирования: не влезает — значит, тема
   делится на два урока.
5. **Код читается как псевдокод.** Каждая нетривиальная строка с комментарием,
   объясняющим «зачем» или результат.

## Примечания о боевой эксплуатации

Где пример работает через Microsoft CSP, добавляется блок **«В боевой
системе»** с указанием, что именно меняется при переходе на КриптоПро и ГОСТ.
Одно место, одна строка — не разрастаясь в параллельный курс.

## Что автор не будет делать никогда

- Не давать пример, который нельзя запустить.
- Не прятать преобразование строки в двоичные данные внутри вспомогательной
  функции без объяснения.
- Не подавать устаревший алгоритм как рабочий вариант без явного предупреждения
  (MD5 и голый хеш пароля — только как разбор ошибки).
- Не заменять объяснение ссылкой на документацию платформы.
- Не превращать курс в разговор о нормативке и юридической силе подписи.
